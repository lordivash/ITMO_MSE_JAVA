1. Считать массив байт из файла в Java можно несколькими способами. https://www.baeldung.com/java-convert-file-byte-array
Какой из способов самый быстрый? Как это изменяется в зависимости от размера файла?

2. В стандартной библиотеке есть несколько реализаций интерфейса Map. Из них два могут корректно работать в многопоточном режиме, но в однопоточном дают пенальти по производительности.
Измерьте насколько ConcurrentHashMap и ConcurrentSkipListMap медленнее чем HashMap в однопоточном режиме. Проверьте в различных сценариях.

3. В Java есть 4 реализации интерфейса java.lang.ref.Reference и есть также обычные сильные ссылки которые создаются автоматически в выражении Object o = new Object();
Но эти ссылки в отличие от обычных сильных ссылок несут некоторый оверхед, поскольку GC с ними обязан работает по особому.
Нужно определить насколько медленнее происходит создание таких ссылок по сравнению с обычными. 
Но поскольку реальные приложения не только создают ссылки, но и еще работу работают, не забывайте эмулировать эту работу с помощью Blackhole.consumeCPU.

4. Вы хотите получить самый быстрый счетчик работающий в многопоточном режиме. Самая простая реализация - делать increment под synchronised блоком. Второй способ - использовать интерфейс Lock. Третий - взять AtomicLong, четвертый - LongAdder.
Сравните какой из способов самый быстрый в зависимости от разной нагрузки.

5. Ваш веб сервер постоянно отправляет очень простые JSON из двух полей - id сообщения и ACK или NAK. Например, {"id":1,"response":NAK}.
Определите, какая библиотека для сериализации работает быстрее GSON или Jackson. Или может самим ручками клеить?

6. Может у вас есть какая-то хорошая идея чтобы можно было померить? Напишите в чятик и если я одобрю, то делайте свой вариант.

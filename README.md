# AUnit

* На вход вашему тестовому фреймворку передаются инстансы Class<?>.

* Некоторые методы в этих классах помечены аннотацией `@ATest`.
* Тест также дополнительно может быть помечен аннотацией `@Ignore` со строковым параметром `reason`. Такой тест не должен запускаться, но должен присутствовать в списке результатов.
* Необходимо выполнить тесты и вернуть список `TestResult`.

Дополнительные ограничения:
* Можно считать, что класс с тестом всегда имеет публичный дефолтный конструктор
* Можно считать, что методы, помеченные аннотацией `@ATest`, являются публичными и не имеют параметров
* Порядок вызова тестовых методов не специфицируется
* Обработка краевых случаев и нештатных ситуаций (не найден файл, не смогли вызвать метод, нарушаются вышеуказанные ограничения, etc.) не требуется.

    * тест должен бросить исключение указанного класса;
    * если исключение не выброшено, тест провален.

* Добавить поддержку аннотаций `@BeforeEach` и `@AfterEach`.
    * методы, помеченные данными аннотациями выполняются до и после каждого теста, кроме помеченных аннотацией `@Ignore`;
* Добавить поддержку аннотаций `@SetUp` и `@TearDown`.
    * методы, помеченные данными аннотациями выполняются до и после выполнения тестов в классе.

# Часть 3 (3.5 балла)

* Поддержать поля внутри тестового класса, помеченные аннотацией `@Rule`.
    * гарантированно наследники `TestRule`;
    * перед каждым тестом им передается предыдущий `Callable<Void>`, исполняющий тест;
    * они этот `Callable<Void>` оборачивают и возвращают результат, который передается следующему `@Rule`
    * переданный `Callable<Void>` нельзя запускать внутри `apply`, но можно запускать внутри возвращенного `Callable<Void>`.
    * `TestRule` применяются в порядке их объявления; самый первый `Callable<Void>` это непосредственный запуск теста + `@BeforeEach`/`@AfterEach` (если имеются)
